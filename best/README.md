# best · 高质量版本

`src/` 那套是"把物理跑通"的最小闭环：box 几何、理想执行器，数字可信但画面像示意图。
这一套是"拿得出手"的版本——同一个模型、同一套运动学，换掉外观和真实性。

```
python best/demo.py                 # 实时窗口，循环播放
python best/demo.py --record        # 录 1080p 视频
python best/demo.py --still         # 渲一张静帧
```

输出都在 `outputs/`，已加入 `.gitignore`。

## 和 src/ 的关系

| | `src/` | `best/` |
|---|---|---|
| 几何 | 原生 box / cylinder | 程序化超椭球圆角网格 |
| 材质 | 纯色 | 程序化纹理 + PBR（金属度/粗糙度） |
| 光照 | 两盏灯 | 三点布光 + 阴影 + 4× MSAA |
| 执行器 | 理想位置伺服 | 延迟 12 ms + 背隙 7 mrad + 编码器量化 |
| 轨迹 | 三次平滑 | 五次多项式（加速度连续） |
| 运动学 | **同一份 `models/so101.xml`** | ← 完全一致 |

两边位置数据可以互相印证：抓取点、预抓取高度、抬升量都是同一套逆解算出来的。

## 技术要点

**程序化网格。** 超椭球 `|x/a|^n+|y/b|^n+|z/c|^n=1`，n 取 3~5 就是注塑件的圆角感。
MuJoCo 自带的 `make_supersphere(e, n)` 参数语义和教科书指数对不上，n=4 会生成尖刺状菱形，
所以顶点和面都是自己按定义采样生成的。

**程序化纹理。** 3D 打印层纹、木纹、拉丝金属、磨砂塑料，全部用 numpy 现场算。
好处是仓库里没有二进制贴图，想调"脏"一点改两个系数就行。

**视觉与碰撞分离。** 机械臂本体不参与接触（`contype=0`），只有指尖的平板参与。
指尖试过用圆角网格直接碰撞，结果接触点落在圆角上、法向倾斜，物体一抬就被挤着往外滑；
换成平面 box 后摩擦才真正用来抗重力。

**非理想执行器。** `control.ServoModel` 在指令侧注入延迟、背隙和量化误差。
仿真里 100% 的成功率对迁移到实物没有参考价值，这些失真必须加。

## 踩坑记录

写在这里是因为每一个都花了不少时间，而且现象和原因隔得远：

| 现象 | 原因 |
|---|---|
| 背景变成贴图、物体表面却是纯色 | `mjTEXTURE_2D = 0`，按直觉写成 2 会变成 skybox |
| 所有材质都渲染成纯色 | 颜色纹理必须放 **slot 1**，放 slot 0 编译不报错但不生效 |
| 纹理数据被忽略 | `MjsTexture` 要显式 `embed = True`，否则当作外部文件加载失败 |
| 连杆变成尖刺菱形 | `make_supersphere` 的 e/n 不是超椭球指数 |
| 旧几何删不掉 | `del body.geoms[0]` 静默无效，要用 `spec.delete(elem)` |
| 物体穿过桌面 | plane 换成 box 时，位置语义从"中心"变成"平面本身" |

## 已知不足

- 没有接入真实网格资产（SO-101 官方 STL），比例对但外形是简化重建
- 材质是近似 PBR，没有法线贴图
- 执行器模型只在指令侧做失真，没有模拟电流环和温漂
- 背景目前是纯色，没有做环境贴图
